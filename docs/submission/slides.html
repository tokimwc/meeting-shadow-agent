01Meeting Shadow Agent
What it does

One sentence, ready before you need it

At the end of each of their turns, a card appears with one English sentence for the engineer to say. Its shape comes from a memo written before the meeting.

m0 — Implementation owner. Staging validation is mine to agree. Production, dates, scope changes and extra effort need internal approval.
“I can confirm the staging validation by Friday. For the production rollout, I need to check internally.”
cites u1 · m0
Inside the memo — the sentence commits Outside it — the sentence defers, naming what needs approval

It never speaks, never joins the call, never sends anything. The engineer reads and decides.

The browser streams straight to AssemblyAI. Cloud Run sees finalized text, never the stream.

Refuse, do not repair

Every claim cites the utterance ids behind it. A suggestion citing an id nobody spoke is rejected outright — a card with invented evidence is worse than no card.

The memo is not a witness

An open item whose only evidence is m0 is dropped. The memo says what needs approval; it is not evidence that anyone asked for it.

What it does not show

The limits, stated plainly

  • Not a studyA developer-authored test suite. Scenarios written by the person building the agent do not generalise to real meetings.
  • Zero is not proofZero failures in twenty trials still leaves a one-sided 95% upper bound near 14%.
  • No outcome claimNothing here shows a real over-commitment was prevented — only that the cards arrive in time and the safety checks hold on the inputs tried.
  • Accent costNon-native speech degrades the transcript on exactly the words a decision turns on. One human take reached the model as “Oh. End of day. Cause visit.”
  • Not zero retentionAssemblyAI offers a TTL. Billing and log metadata outlive it.

Two prompt changes made the suggestions worse and were reverted. Both runs are in the repository, with the numbers that sent them back.
